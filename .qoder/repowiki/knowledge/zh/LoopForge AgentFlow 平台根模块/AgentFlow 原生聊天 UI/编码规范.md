- 所有 HTTP 请求统一走 `api.js` 导出的 `api()` / `write()`，错误被包装成带 `status` 字段的 Error 对象，由上层 `chat.setError` 或 try/catch 处理。
- 持久化偏好（主题、侧栏宽度、executor、model、pins、环境可见性）通过 `localStorage` 读写，并以 `agentflow.native-chat.*` 或 `loopforge.assistant.*` 命名空间隔离。
- 跨窗口通信采用 `window.parent.postMessage` 配合 origin 校验，事件类型以 `agentflow-chat-*` 前缀区分（如 `agentflow-chat-open-view`、`agentflow-chat-session`）。
- 可复用逻辑抽离为独立 `.js` 模块（如 `activity.js`、`message-queue.js`、`session-status.js`、`effort.js`），组件只 import 纯函数，避免在 JSX 中内嵌业务规则。
- UI 组件与样式分离：每个 `.jsx` 组件通常对应同名的 `.css` 文件，通过 `import './xxx.css'` 在组件入口处加载。
- 测试文件与源码一一对应，放在 `tests/` 目录下，文件名与源文件同名（如 `main.test.jsx`、`message-queue.test.mjs`），使用 Vitest 的 ESM 风格导入。
