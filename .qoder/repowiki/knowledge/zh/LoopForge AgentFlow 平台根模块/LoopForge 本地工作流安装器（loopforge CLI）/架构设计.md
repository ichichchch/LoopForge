模块以 Python 包 `devflow_cli`（`src/devflow_cli/`）为入口，通过 `pyproject.toml` 的 `[project.scripts]` 暴露 `loopforge` 命令。
- 分层结构：`cli.py` 仅负责 `argparse` 子命令解析与人类可读 / JSON 输出；`core.py` 实现资产发现（`asset_root()`）、状态持久化（`.devflow/install-state.json`）、快照/复制逻辑以及 `materialize_portable` / `materialize_classic` 两大编排函数；`editions.py` 集中声明两个 edition（`classic` / `portable`）的元数据、宿主集合与入口映射；`targets/` 下每个宿主一个模块（claude/codex/cursor/codebuddy/pi/dsh/hermes/qoder），由 `targets/__init__.py::load` 通过 `import_module` 动态加载。
- 双 Edition 模型：Classic 从 `.codebuddy/.codex/.cursor/.claude/` 等宿主原生目录拷贝完整包；Portable 从 `skills/` 读取 `manifest.json` 中的 skill_sets，按宿主差异（`.agents/skills`、`.codebuddy/skills`、`.hermes/skills`、`.pi/skills`、`.dsh/skills`）分别物化到项目根目录下。
- 宿主适配器边界：`core.materialize_*` 根据 host 分支调用各宿主的 adapter installer（如 `skills/devflow/adapters/{cursor,claude}/install_adapter.py`、`adapters/codebuddy/install.py`），将通用 skills 适配为宿主可识别的目录结构。
- 插件扩展点：顶层 `dsh-plugin/`（Node.js，`package.json` + `index.js`）和 `hermes-plugin/`（Python，`plugin.yaml`）作为独立 npm/Python 插件，不进入 `devflow_cli` 包。
- 辅助工具：`tools/tcmcp/` 是独立的 tencent-cloud MCP 服务器（FastAPI + Vite 前端），与 CLI 无代码依赖，仅共享仓库。
- 测试：`tests/e2e/` 使用自定义 harness 模拟 agent 执行真实 workflow；`tests/live/` 与 `scripts/test-live.sh` 用于在线宿主集成测试。
