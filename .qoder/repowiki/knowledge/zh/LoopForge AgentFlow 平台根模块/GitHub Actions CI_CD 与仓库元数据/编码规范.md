- 每个工作流在 PR/push(main, master) 触发时显式声明 `permissions: contents: read`，仅在需要写操作（如 release）时才提升为 `contents: write` / `packages: write` / `id-token: write`。
- 长耗时工作流（platform、e2e、release*）使用 `concurrency.group` 配合 `cancel-in-progress: true/false` 控制同一 PR 或 tag 下重复运行的行为。
- 需要对外部服务稳定的 job（platform-required、e2e-gate）以 `if: always()` 运行，并通过 shell 脚本检查 `needs.*.result` 是否均为 success，从而提供稳定的分支保护 check 名。
- 跨平台矩阵通过 `strategy.matrix.include` 显式列出组合，并在注释中说明为何某些组合需要特定 runner（如 Ubuntu 24.04 用于 Python 3.8），避免依赖隐式默认值。
- 所有外部脚本统一通过 `bash scripts/*.sh` 或 `python3 scripts/*.py` 调用，工作流本身只编排步骤而不内联复杂逻辑。
- 敏感 token（GITLEAKS_TOKEN、NPM_TOKEN、GH_TOKEN）一律通过 `${{ github.token }}` 或 secrets 注入，并以 `echo "::add-mask::$token"` 掩码输出。
